# lock-{{PROJECT}}

Generated by decision-lock for this project. Every decision in the decision log has a test and at least one mutant; this skill runs them on a throwaway copy of the system and keeps the evidence. One CLI does everything: `scripts/lock.sh` (Windows: `scripts/lock.ps1`). Every subcommand prints one JSON object, `{"ok":true,...}` or `{"ok":false,"error":...}`.

**A check you have never seen fail proves nothing.** That is why `selftest` exists, and why this skill is not handed over until it has failed on purpose once and passed again.

Decisions: `decisions/D*.md` (one file per decision: verbatim text, rule class, tests, mutants, status). Decision log: `{{DECISION_LOG}}`.

## Launch

```
scripts/lock.sh launch
```

Builds the Postgres + pgTAP image if missing and starts the throwaway container `{{CONTAINER}}` (data in memory, project mounted read-only). Never point it at a live database; it refuses any container it did not label.

## Doctor

```
scripts/lock.sh doctor
```

Checks Docker, the image, the container, a hash tool, the schema files, and that every decision has a test and a mutant. `ok:false` lists what is missing. Run it first when anything looks wrong.

## Drive

```
scripts/lock.sh run                # every decision
scripts/lock.sh run D001-D010      # a slice
scripts/lock.sh run D003 D005      # chosen decisions
```

For each decision: the pgTAP test must pass on a fresh database, then each mutant is applied to a fresh database and the test must fail by a named assertion (`DNNN-xx`). A mutant is killed only by a named failing assertion; a setup crash is not a kill; a survivor means the test is too weak. A decision with no test yet fails with `DNNN: not built yet` so the gap stays visible. Drive with `{{DRIVE}}`.

Adding a decision from one example: see `templates/teach-example.md` of decision-lock (one good example, one bad example, the builder writes the test and the mutant).

## Evidence

```
scripts/lock.sh evidence
```

Writes `handoff/evidence/EVIDENCE.md`: the verdict line (`LOCK VERDICT: LOCKED` or `NOT LOCKED`), the per-decision kill matrix (`handoff/evidence/kill-matrix.txt`), and "Proof it can fail" from the self-test (`handoff/evidence/selftest.json`). Show this file when you report a change as done.

Prove the check can fail, before trusting it and after any change to the engine:

```
scripts/lock.sh selftest D003
```

It appends one mutant to the last schema file (breaks the decision on purpose), shows the run FAILS by a named assertion, restores the file and compares sha256 hashes (`hash_match` must be true), then shows the run PASSES.

## Cleanup

```
scripts/lock.sh cleanup
```

Removes the container `{{CONTAINER}}`. Slices run in parallel only in separate copies with separate container names (`decision-lock/scripts/new-slice.sh`); isolation: {{ISOLATE}}.

## Helpers

- `engine/scripts/db.sh` (`build`, `start`, `fresh`, `stop`), `engine/scripts/run_decision_tests.sh`, `engine/scripts/env.sh`: the decision-lock engine, copied unchanged. Settings: `decision-lock.env` in the project root.
- `scripts/lock.ps1`: PowerShell entry point; it calls `lock.sh` through bash.
- Roles for a new slice (builder, certifier, independent run, fix loops): the decision-lock skill (`new-slice.sh`, `pipeline.sh`).
- Exit code of every subcommand: 0 when `ok` is true, 1 when false.
